# 清晰采图

面向大华 / 华睿工业相机的 Windows Python + Qt 采图工具。
默认用高质量 JPEG 替代 BMP，可在原始分辨率下裁剪一个矩形 ROI 后保存。

## 启动

需要 **Windows 64 位、Python 3.10 或更高版本**。真机采集还需要安装
MV Viewer / IMV SDK Runtime（包括 GigE 或 USB 驱动）。

双击 `start.bat`；首次启动会在项目内创建 `.venv` 并安装依赖。
也可以在 PowerShell 中运行：

```powershell
.\start.ps1
# 无相机体验与验证
.\start.ps1 -Demo
# 指定创建虚拟环境时使用的 Python
.\start.ps1 -Python 'C:\path\to\python.exe'
```

已准备好的环境也可直接启动：

```powershell
.\.venv\Scripts\python.exe main.py
.\.venv\Scripts\python.exe main.py --demo
```

如系统的 PowerShell 脚本策略阻止启动，使用 `start.bat`。
程序不会修改全局执行策略；运行脚本时仅指定本次进程的策略。

## 采图

1. 先关闭 MV Viewer 中对该相机的采集或连接，避免设备被占用。
2. 点击“刷新设备”，选择相机，也可输入 GigE 相机的 IP 后连接。
   IP 输入非空时优先使用 IP；模拟模式忽略 IP。
3. 连接后自动开始预览；也可单独停止或重新开始预览。
4. 选择保存目录。点击“保存一张”或按 `Ctrl+S`；定时保存默认每秒一张。
5. 需要裁剪时启用“绘制 / 调整 ROI”，拖出矩形。拖动框内可移动，拖动四角可改变大小。
   也可输入 X/Y/宽/高并点击“应用坐标”。清除 ROI 恢复保存完整相机输出。
6. 调节曝光、增益或自动模式后，点击对应“应用”。程序串行停采、修改、回读后恢复预览；
   调参会停止定时保存，需要重新手动开始。点击“回读相机实际值”刷新自动模式下的读数。

画面上方有“放大”“缩小”按钮和当前缩放比例；鼠标滚轮也可缩放。
按钮以画面中心缩放，滚轮以鼠标位置缩放，手动范围为 1%–3200%。
实时预览刷新会保留手动缩放比例。关闭 ROI 绘制模式后拖动平移；
“1:1 像素”恢复 100%，“适应窗口”恢复自动适配。缩放仅影响显示，保存图片和 ROI 坐标仍使用原始像素。
曝光、增益、SDK 路径等设置位于右侧可滚动面板内。

## 清晰度与体积

- **JPEG**：默认质量 95，可调 80–100，彩色使用 4:4:4、不进行色度降采样，并优化编码。
  质量 100 仍是有损 JPEG，不等于无损。可以从 95 开始，用 90–95 比较细节与体积。
- **PNG**：无损保存转换后的输出像素。纹理复杂、噪声较高时文件可能仍较大。
- **ROI**：只裁剪，不缩放，不改变保留区域的像素分辨率；不把预览截图或 ROI 线框写入图片。
- **同帧比较**：等待一张新图，在内存中分别编码 JPEG 与 PNG，显示完整保存区域的编码体积，
  并展示中心最多 512×512 像素的原尺寸对比；不额外写入文件。
- 输出是 **8 位灰度或 RGB**，黑白图保留单通道。Bayer 由 SDK 双线性去马赛克；
  高位深源格式通过 SDK 转换为 8 位，状态栏显示源格式。PNG 并不保留转换前 RAW/高位深信息。
  不支持的源格式会显示 SDK 错误，不会静默保存损坏图像。
- 曝光过长的运动模糊、失焦和高增益噪声无法靠图片格式修复。工具不会自动锐化、降噪或缩放。

## 行为说明

- 第一版一次连接一台相机，支持手动保存、间隔抽样保存；不是连续录像或每帧无丢帧采集。
- 保存请求在相机线程清理旧缓冲后等待下一张图。若上一请求还没完成，定时器跳过该时间点，
  不积累补拍；请求超时不重复保存上一张。极长曝光（连续 10 秒无图）会报超时并断开。
- 保存队列上限为 8 张、原始像素合计 256 MiB（含正在处理的图片）；达到任一上限时暂停定时保存，
  提示本次没有入队。编码临时内存不包含在该原始像素额度中。
- 磁盘失败会取消剩余排队任务，并提示数量。修复目录或空间后，手动保存或重新开始定时保存即可重试。
- 文件使用时间戳、会话标识和序号命名；采用同目录临时文件完成后发布，不覆盖已有文件。
- 正常退出时取消尚在等待新帧的请求，完成已经进入保存队列的任务，并释放相机资源。
- 连接仅读取曝光、增益等实际值；预览临时切换为自由采集，正常断开时恢复原触发模式。
  用户手动应用的曝光与增益保留为相机运行配置，不执行相机断电保存。
- 软件 ROI 坐标相对于**相机当前输出**，不会自动重置相机已经配置的硬件 ROI。
  ROI 按设备身份与输出尺寸记忆；尺寸变化后仅恢复匹配该尺寸的有效 ROI。
- UI 配置通过 Windows 当前用户的 QSettings 保存（`GetPicture/CaptureTool`）。
  日志写入 Qt 的当前用户本地应用数据目录，文件名 `capture.log`，自动轮转。

## SDK 排查

默认查找：

```text
C:\Program Files\HuarayTech\MV Viewer\Runtime\x64\MVSDKmd.dll
```

其他安装位置可以在右侧选择 `MVSDKmd.dll`，或设置 `HUARAY_MV_VIEWER_ROOT`
为 MV Viewer 根目录（也可为 DLL 文件）。须保持 DLL 的依赖文件位于原运行库目录，
不要只复制单个 DLL。Python 与运行库都应为 64 位。

设备列表为空时，先确认 MV Viewer 能发现设备、GigE 网卡处于对应网段、USB 驱动已安装。
工具不修改网卡、相机 IP、固件或其他网络配置。

## 验证

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts\verify_demo.py
```

自动化测试包含模拟 SDK 与 Qt 离屏界面测试，不依赖真机。
`verify_demo.py` 在 `build/verification` 生成界面截图、示例 ROI 图片和编码比较报告。

真机验收步骤：记录原触发、曝光、增益和像素格式；验证设备枚举与预览、曝光增益回读、
单张和定时采图、ROI 边界、文件尺寸、停止后重新连接；正常断开后在 MV Viewer 核对触发恢复。
最后按需要恢复测试前的曝光、增益。模拟通过不代表 USB/GigE 真机已验收。

本版本不包含 EXE 打包、多个 ROI、多相机并采、硬件触发或硬件 ROI 编辑。
相机接入参考版本见 `THIRD_PARTY.md`。
